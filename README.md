# Concurrent Search Bot

Учебный Telegram-бот на aiogram 3, который ищет по одному запросу в Wikipedia, GitHub и Stack Overflow.

Бот показывает до двух результатов от каждого источника. Для GitHub выводит звёзды и основной язык репозитория; для Stack Overflow — число ответов, рейтинг и наличие принятого ответа.

## Как устроен поиск

Telegram-обработчик передаёт запрос в `SearchService`. Сервис запускает три асинхронных провайдера конкурентно и получает отдельный `ProviderOutcome` для каждого источника. Ошибка одного источника не мешает показать результаты остальных. Ответ собирается из трёх секций и отправляется пользователю.

Общая `aiohttp.ClientSession` создаётся при запуске бота и закрывается при его остановке. Общий семафор ограничивает число одновременно выполняющихся провайдеров в одном процессе бота.

## Требования и запуск

Нужен Python 3.12–3.14 и токен Telegram-бота от BotFather.
```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -e .
```

## Ограничения и обработка ошибок

В текущей конфигурации одновременно работают не более трёх провайдеров. Работа одного провайдера после получения места ограничена 20 секундами; весь поиск одного пользовательского запроса, включая ожидание места, — 30 секундами. HTTP-сессия также настроена с таймаутом 20 секунд.

Пустая выдача, сетевая ошибка и превышение времени ожидания отображаются отдельно для каждого источника. При общем дедлайне бот сохраняет успевшие результаты и отмечает остальные источники как не завершившиеся вовремя.

Поиск Wikipedia использует англоязычную Wikipedia; тексты, полученные из внешних API, не переводятся. Авторизация GitHub-токеном не настроена, поэтому действуют ограничения для запросов без токена. Поле `backoff`, которое может вернуть Stack Exchange API, **пока не учитывается**; проект не предназначен для частых автоматических запросов к этому API. Текущая версия также не гарантирует разбиения слишком длинного ответа на несколько сообщений Telegram.

## Проверка конкурентности

В `src/search_bot/probes/` находятся отдельные пробники для ручной проверки провайдеров, конкурентного запуска и нагрузки. Нагрузочные эксперименты используют подставные провайдеры и не отправляют запросы к внешним API.

Без ограничения в эксперименте с пятью одновременными поисками по три провайдера наблюдалось до 15 активных операций; при общем лимите 3 — не более 3.
